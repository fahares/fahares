# صفحۀ نگهداری بیرون از میزبان (مورد ۱۳۶، گام ۱۴.۴۰۶)

صفحۀ `fahares-down` روی خود میزبان است. وقتی خود میزبان ریستارت یا خاموش است، هیچ‌چیز پاسخ نمی‌دهد. این Worker کلودفلر
آن خلأ را پر می‌کند. پروکسی کلودفلر در ایران کند است، پس در زمان عادی روشن نیست.

## کار Worker

- **زمان عادی:** رکوردهای `fahares.net` و `www` خاکستری‌اند (DNS-only) و بازدیدکننده مستقیم به میزبان می‌رسد.
- **cron هر دقیقه:** Worker نشانی `https://fahares.net/up` را می‌خواند.
  - «پاسخ نداد» یعنی خطای اتصال، ۱۰ ثانیه بی‌پاسخی، یا صفحۀ ۵۲x/۵۳۰ خود کلودفلر.
  - هر پاسخ HTTP دیگری، حتی ۵۰۳ از `fahares-down` یا ۵۰۲ از Traefik، یعنی میزبان روشن است. آن‌وقت چیزی عوض نمی‌شود.
- **قطعی میزبان:** اگر دو وارسی پشت سر هم (به فاصلۀ ۲۰ ثانیه) پاسخ نگیرند، رکوردها نارنجی (proxied) می‌شوند. از آن پس
  هر درخواست به Worker می‌رسد:
  - اگر میزبان در ۱۵ ثانیه پاسخ دهد، همان پاسخ میزبان به بازدیدکننده می‌رسد.
  - اگر پاسخ ندهد، صفحۀ نگهداری می‌آید: [index.html](../index.html) با عنوان «سرور فهارس در حال نگهداری است»، کد ۵۰۳،
    `Retry-After: 120` و `X-Robots-Tag: noindex`. صفحه هر چند ثانیه `/up` را می‌خواند و وقتی سایت برگشت، خودش باز می‌شود.
- **بازگشت:** وقتی میزبان دو بار پشت سر هم پاسخ داد، رکوردها با TTL ‏۶۰ ثانیه خاکستری می‌شوند.
- **نگهداری برنامه‌ریزی‌شده:** با `scripts/dev/maintenance on` رکورد TXT ‏`_maintenance.fahares.net` ساخته می‌شود. تا این
  رکورد هست، رکوردها نارنجی می‌مانند. یادداشت و زمان تقریبی بازگشت هم در صفحه نشان داده می‌شود.
- **مهلت جابه‌جایی:**
  - تشخیص قطعی حدود ۱ تا ۲ دقیقه است. سپس باید TTL ‏۶۰ ثانیه بگذرد. برخی DNSهای ایران رکورد را بیش از TTL نگه می‌دارند.
  - پس ریستارت کوتاه معمولاً پیش از جابه‌جایی تمام می‌شود و این روش قطعی‌های بلندتر را پوشش می‌دهد.
  - برای نگهداری برنامه‌ریزی‌شده، `maintenance on` را چند دقیقه پیش از ریستارت بزنید.
- **هزینه:** طرح رایگان Workers کافی است. cron روزی ۱٬۴۴۰ اجرا دارد، و Worker فقط وقتی رکوردها نارنجی‌اند به بازدیدکننده پاسخ می‌دهد.
- **IP واقعی بازدیدکننده:** در حالت نارنجی، اپ آن را از `CF-Connecting-IP` می‌گیرد
  (`App\Http\Middleware\CloudflareClientIp`)، و فقط وقتی درخواست از بازه‌های کلودفلر آمده باشد.

## راه‌اندازی (کار کاربر در داشبورد کلودفلر)

1. **SSL/TLS → Overview:** حالت را **Full (strict)** کنید. اگر Flexible باشد، در حالت نارنجی حلقۀ ریدایرکت پیش می‌آید. تا
   رکوردها خاکستری‌اند، این تنظیم اثری ندارد.
2. **SSL/TLS → Edge Certificates:** گواهی Universal باید Active باشد.
3. **DNS → Records:** TTL رکوردهای `fahares.net` و `www` را از Auto به **1 min** برسانید.
4. **API token:**
   - My Profile → API Tokens → Create Token → الگوی **Edit zone DNS**.
   - در Zone Resources گزینۀ Include → Specific zone → `fahares.net` را بگذارید. سپس Create Token را بزنید و آن را کپی کنید.
5. **نگه‌داشتن token روی لپ‌تاپ،** برای `scripts/dev/maintenance`. در ترمینال خودتان بزنید و token را paste کنید؛ روی صفحه
   نمایش داده نمی‌شود:

   ```bash
   read -rs T && printf '%s' "$T" > ~/.fahares/cloudflare-dns-token && chmod 600 ~/.fahares/cloudflare-dns-token && unset T
   ```

6. **Zone ID:** در صفحۀ Overview زون، ستون راست. این شناسه رمز نیست و در `ZONE_ID` همین پوشه در
   [wrangler.toml](wrangler.toml) می‌نشیند.
7. **استقرار Worker** از همین پوشه، در ترمینال خودتان:

   ```bash
   npx wrangler login
   npx wrangler deploy
   npx wrangler secret put CF_API_TOKEN
   ```

   فرمان سوم token را می‌پرسد؛ همان token گام ۴ را paste کنید.
8. **Workers Routes:** در Websites → fahares.net → Workers Routes، برای هر سه route حالت Request limit failure را
   **Fail open** کنید. اگر سقف رایگان پر شود، درخواست مستقیم به میزبان می‌رود و خطایی برای بازدیدکننده پیش نمی‌آید.

## آزمون

- **cron:** با `npx wrangler tail` هر دقیقه باید `failover check: up` دیده شود.
- **صفحه بی دست زدن به میزبان:**
  - یک رکورد A نارنجی `failover-test` به `192.0.2.1` بسازید. این نشانی آزمایشی است و به جایی نمی‌رسد.
  - `curl -sI https://failover-test.fahares.net/` باید ۵۰۳ با `Retry-After: 120` بدهد، و در مرورگر صفحۀ نگهداری دیده شود.
  - سپس رکورد را پاک کنید.
- **جابه‌جایی رکوردها:**
  - `scripts/dev/maintenance on --no-lock "آزمون"` را بزنید. رکوردها نارنجی می‌شوند، و سایت از راه کلودفلر همچنان کار
    می‌کند: `curl -sI https://fahares.net/` ‏`server: cloudflare` و ۲۰۰ می‌دهد.
  - سپس `scripts/dev/maintenance off` را بزنید. پس از ۱ تا ۲ دقیقه `scripts/dev/maintenance status` باید `proxied=false` نشان دهد.
- **قطعی واقعی:** در نخستین ریستارت برنامه‌ریزی‌شدۀ میزبان، به‌جای `maintenance on`، رفتار خودکار هم دیده شود.
  رکوردها پس از حدود ۲ دقیقه باید نارنجی شوند و پس از برگشت میزبان، خاکستری.

منطق Worker آزمون دارد (`node --test docker/down/cloudflare/failover.test.mjs`، بی هیچ بسته‌ای).
